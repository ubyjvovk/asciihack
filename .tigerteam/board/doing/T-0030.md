## Goal
Play AsciiHack in a browser with the same TypeScript client: a small
Node WebSocket server spawns `nh-bridge` per connection and relays its
JSON lines; the browser runs `NethackSession` + the existing `App` over a
DOM "terminal" (a `<pre>` grid of coloured cells) — classic, fps and
ortho modes exactly as in the tty, keys included. This is the thin-client
transport; the three.js viewport (T-0031) then replaces the fps/ortho
viewport with AsciiCity's shader styles. Static WASM hosting is a later
transport.

## Context
- Read `docs/architecture.md` §3 (protocol), §4, §6, `docs/engine.md`,
  `docs/ui.md`, `docs/terminal.md`. The tty stack: `src/engine/bridge.ts`
  (`spawnBridge`: messages/batches/reply/kill/exited), `src/engine/session.ts`
  (`NethackSession`, `runSession`), `src/ui/app.ts` (`App` over a `TermIO`),
  `src/term/screen.ts` (`Screen`, `diff`, `TermIO`), `src/term/input.ts`
  (`parseKeys`, `KeyEvent`), `src/term/tty.ts` (the only Node-tty file).
- **Shared code must stay browser-clean.** `src/engine/session.ts`,
  `src/ui/*`, `src/render/*`, `src/term/screen.ts`, `src/term/input.ts`
  must import nothing from `node:*`. Today `src/engine/session.ts` imports
  `EventEmitter` from `node:events` — replace it with a tiny typed emitter
  in the same file (same `on`/`off`/`emit` API used by the UI). Move any
  Node-only helper out of shared modules; `src/engine/bridge.ts` stays
  Node-only but export its **transport interface** (`BridgeTransport`:
  `messages`/`batches` async iterables, `reply`, `kill`, `exited`) so the
  session and `runSession` accept either transport.
- `server/ws-server.ts` (Node, uses the `ws` package already in
  `package.json`): `npm run web:server [--port 8790] [--playgrounds DIR]`.
  On a connection to `/play?name=<name>` it validates the name (reuse the
  rule from `bin/asciihack-lib.sh`: `[A-Za-z0-9_-]{1,20}`), copies the
  bridge playground to `<playgrounds>/<name>/` on first use (default
  `~/.asciihack/players/`), spawns `nh-bridge` via `spawnBridge`, forwards
  every bridge line to the socket as a text frame and every socket frame
  to the bridge's stdin; kills the bridge when the socket closes; logs one
  line per session start/end. One bridge per socket, no sharing. Bind to
  `127.0.0.1` by default (`--host` to change) — it is a game server with
  no auth.
- `web/src/ws-bridge.ts`: `WsBridge` implementing `BridgeTransport` over a
  browser `WebSocket` (line framing is one message per frame; reconnect
  not needed).
- `web/src/dom-term.ts`: `DomTerm implements TermIO`: renders a
  `ScreenGrid` into a `<pre>` of `<span>` runs (one span per run of equal
  fg/bg — do not create a span per cell), monospace font, cell size
  measured once; `columns`/`rows` derived from the container size
  (≥ 80×24, target the window); `onKey` from `keydown` events mapped to
  `KeyEvent`s (arrows, F1–F12, Enter, Escape, Backspace, Tab, Ctrl+letter,
  printable characters, Shift/Alt/Ctrl flags — reuse `KeyEvent`'s shape;
  prevent default for handled keys); `onResize` from `ResizeObserver`.
  Since the `Screen` writer emits ANSI, give `DomTerm` a `paint(grid)`
  path instead: the `App` should accept a `TermIO` that paints grids
  directly — add an optional `paintGrid?(grid)` to `TermIO` that the
  `Screen` uses instead of the ANSI diff when present (thin change in
  `src/term/screen.ts`… which is not in scope; if `App`/`Screen` need a
  change, block with `## Questions` and the PM will widen scope).
- `web/src/main.ts`: reads `?name=`, opens the socket (`ws://<host>/play`
  — the Vite dev server proxies `/play` to the server port, see
  `web/vite.config.ts`), builds `NethackSession` + `App` with `DomTerm`,
  default mode `fps` (renders the CPU raycaster into the grid until
  T-0031 swaps in the WebGL viewport), theme from `?theme=`. A minimal
  `web/index.html` with the `<pre>` and a "connecting…" line.
- `web/vite.config.ts`: root `web/`, `resolve.alias` `@engine` →
  `../src/engine` etc. or plain relative imports; `server.proxy['/play']`
  → `ws://127.0.0.1:8790`; `build.outDir` `dist-web/`.
- `web/tsconfig.json` extends the root one with `lib: ["ES2022","DOM"]`,
  includes `web/src` and `src` (but not `src/term/tty.ts`, `src/cli.ts`,
  `src/engine/bridge.ts`, `server/`).
- Tests (node): `tests/ws-bridge.test.ts` with a fake `WebSocket` object
  (line in → message out, reply → send, close → exited); `tests/dom-term.test.ts`
  with a minimal fake `document` (a run of equal-colour cells produces one
  span; a keydown for ArrowLeft yields `Left`).
- Manual check (report): `npm run web:server` + `npm run web:dev`, open
  `http://127.0.0.1:5173/?name=tester`, play a few turns in classic and
  fps; `S`/`y` closes cleanly. The worker container has no browser: do
  the steps that don't need one (server start, socket handshake with a
  script) and say so; the PM does the browser run.
