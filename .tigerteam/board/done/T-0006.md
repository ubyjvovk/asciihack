## Goal
Three pure modules every terminal mode needs: the ASCII quantizer that
turns a `FrameBuffer` into a `ScreenGrid` using AsciiCity's ramp/gamma
formulas (`docs/architecture.md` §5.4), the `Screen` writer that paints a
`ScreenGrid` with minimal ANSI output (§6.1), and the key parser (§6.2).

## Context
- Read `docs/architecture.md` §5.1, §5.4, §6.1, §6.2. Types are PM-owned in
  `src/model/types.ts` (`FrameBuffer`, `ScreenGrid`, `ScreenCell`).
- `src/render/ascii.ts`: `DEFAULT_RAMP` (the 68-glyph string in §5.4 —
  copy it exactly; it starts with a space and ends with `$`),
  `glyphIndex(lum, count, gamma)`, `quantize(fb, opts?: QuantizeOptions):
  ScreenGrid` and `quantizeInto(fb, grid, opts?)` (reuses the grid's cell
  objects — no per-frame allocation). Defaults: exposure 1.7, gamma 0.45.
  Overlay cells print `overlayCh` in `overlayRgb` (exposed, clamped) on
  black. Never let a non-overlay cell produce a character outside the ramp.
- `src/term/screen.ts`: `diff(prev: ScreenGrid | null, next: ScreenGrid):
  string` — emits `CSI row;col H` moves only when the cursor is not already
  there, `CSI 38;2;r;g;b m` / `CSI 48;2;r;g;b m` only when the colour
  changes, skips runs of identical cells, and ends with `CSI 0 m`. `null`
  prev (or a size change) = full repaint after `CSI 2 J`. `class Screen`
  wraps it over a `TermIO {write(s), columns, rows, onResize(cb), onKey(cb)}`
  with `paint(grid)`, `invalidate()`, `enter()` (alt screen `CSI ?1049 h`,
  hide cursor `CSI ?25 l`) and `leave()` (reverse, reset SGR). Optional
  `CellStyle` bits (bold/inverse) via SGR 1 / 7 on `ScreenCell.attrs` are
  **not** in the PM type — if you need them, add an optional
  `attrs?: number` field only through a `## Questions` block; otherwise
  express inverse video by swapping fg/bg.
- `src/term/input.ts`: `parseKeys(buf: Uint8Array, pending: Uint8Array):
  {events: KeyEvent[], rest: Uint8Array}` — a pure incremental parser;
  `KeyEvent {key: string; ctrl: boolean; shift: boolean; alt: boolean;
  seq: string}`. `key` is the character for printable input, else one of
  `Escape Enter Tab Backspace Up Down Left Right Home End PageUp PageDown
  Insert Delete F1 F2 F3 F4 F5 … F12`. Recognise CSI (`ESC [ … final`),
  SS3 (`ESC O x`), modifiers `;2` (shift) `;3` (alt) `;5` (ctrl), `ESC x`
  as alt+x, bytes 1–26 as `Ctrl+letter` (`key` = the lower-case letter,
  `ctrl: true`; byte 13 is `Enter`, 9 `Tab`, 127/8 `Backspace`). A lone
  ESC stays in `rest` (the caller applies the 25 ms timeout and calls
  `flushEscape()` which returns the `Escape` event). UTF-8 multi-byte
  printables decode to one event.

## Rework (attempt 2)

Good work: the quantizer matches §5.4, the diff is tight, the parser grammar
is right, and the 70-glyph count is correct (the PM fixed the doc). Three
bugs found by reading the code; fix all three and add the named tests.

1. **`Screen.paint` breaks with `quantizeInto`** (`src/term/screen.ts`). It
   stores the caller's grid object as `prev`. The intended per-frame loop is
   `quantizeInto(fb, grid); screen.paint(grid)` with one reused grid whose
   cells are mutated in place — so the next `paint` diffs the grid against
   itself and emits nothing forever. Fix: `Screen` keeps its own private copy
   of the last painted cells (copy `ch`/`fg`/`bg` into an internal grid,
   reusing that internal storage frame to frame — no per-frame allocation
   after the first). Test `repaints a cell mutated in place in the same grid
   object`: paint a grid, change one cell's `ch` in the same object, paint the
   same object again → the output contains a move to that cell and its char.

2. **Invalid UTF-8 wedges the parser** (`src/term/input.ts`). `decodeUtf8`
   returns `null` both for "incomplete at buffer end" and "invalid byte"
   (bare continuation 0x80–0xBF, lead 0xC0/0xC1/0xF8+, bad continuation).
   `parseKeys` then `break`s, the bad byte stays in `rest` forever, and every
   later key is stuck behind it (a Latin-1 terminal or a stray byte kills
   input). Fix: distinguish the two — incomplete → hold; invalid → skip that
   one byte and continue. Tests: `skips an invalid UTF-8 lead byte` (0xFF
   then `a` → one event `a`, empty rest); `skips a bare continuation byte`;
   `holds a partial UTF-8 sequence` (first two bytes of `€` → no events,
   rest length 2, then the third byte completes it).

3. **Unknown escape sequences leak as keystrokes** (`src/term/input.ts`).
   A CSI/SS3 with an unrecognised final (mouse reports `ESC [ M …`,
   `ESC [ < …`, focus events `ESC [ I`/`ESC [ O`, DA responses) returns
   `null`, so only the ESC is skipped and `[`, `M`, digits… become printable
   events fed to NetHack. Fix: consume the whole sequence (up to and
   including its final byte; for `ESC [ M` also the three following bytes;
   for SGR mouse `ESC [ <` up to the `M`/`m` final) and emit **no** event.
   Tests: `drops an unknown CSI sequence whole` (`ESC [ I` then `k` → only
   `k`); `drops an SGR mouse report` (`ESC [ <0;10;20M` then `j` → only `j`).

Keep the existing 24 tests green. Done looks like: 24 + the 6 tests above
pass, `docs/terminal.md` mentions the private copy in `Screen` and the
"unknown sequences are dropped" rule.
