## Goal
Bring the sibling project's voxel construction kit into this repo as strict
TypeScript, behaviour-identical: `vendor/afterburn/src/voxel/{kit,palette,mesh}.js`
→ `web/src/voxel/{kit,palette,mesh}.ts`. Everything else in the GPU wave
(`docs/gpu.md`) builds its geometry with this kit, so the API must match the
original exactly — afterburn model code pasted here later must compile with
no edits.

## Context
- **The sources are vendored in-repo at `vendor/afterburn/` (read-only).**
  `~/afterburn` itself is **not** visible inside the worker container —
  read the vendored copy, and diff your port against it before you hand
  off.
- **Read first**: `docs/gpu.md` §2 and §4 (this repo, the wave's contract),
  then `vendor/afterburn/docs/ARCHITECTURE.md` §1 "Voxel kit" — that is the API
  contract you are preserving. Then the three source files
  (`kit.js` 256 lines, `palette.js` 85, `mesh.js` 180). The user has
  authorised copying from `~/afterburn` freely.
- `kit.js` is pure data, no three.js: `makeRng`, `noise3`, `fbm3`,
  `VoxelBuilder` (`box/voxel/fill/shell/line/blob`, transforms
  `at/rotY/mirrorX/bothX/bothZ/stamp`, `part/root/anchor/light`, the seeded
  helpers `range/int/chance/pick/noise/fbm`, `build(name)`).
- `palette.js` is `PAL`, `MAT`, `FX`, `hexOf`, `matOf`.
- `mesh.js` is `EMISSIVE_RANGE`, `GeoWriter`, `hiddenFaces`, `partGeometry`,
  `buildModelObject`, `bakeModel`; it imports `three/webgpu`, which resolves
  both in node and under vite here (three r185 is already a dependency — do
  not add any npm package).
- Keep names, argument order and defaults. Give the plain records real
  exported interfaces: `VoxelBox`, `VoxelPart`, `VoxelModel`, `VoxelLight`,
  `MatPreset`, `BuilderOptions`. Colours stay `number` (0xRRGGBB) or palette
  key `string`; a union type `ColorRef = number | string` is fine.
- Port rules from `AGENTS.md`: TS strict, named exports only, no `any`
  (`unknown` + narrowing), relative imports end in `.js`, one-line JSDoc on
  every exported function/class.
- **Two typecheckers must pass.** `tests/` is compiled by the root
  `tsconfig.json`, which has `noUncheckedIndexedAccess: true` and **no DOM
  lib** — so index typed arrays with `!` the way `src/render/raycast.ts`
  does, and do not reference DOM types (`HTMLCanvasElement`, …) anywhere in
  these three files. `web/tsconfig.json` already includes
  `src/voxel/**/*.ts` (the PM added it); do not edit either tsconfig.
- `vendor/afterburn/src/voxel/pixelfont.js` is **not** part of this ticket.

## Questions

**Blocker: `~/afterburn` is not accessible from the worker container, so I
cannot port it.** The ticket says "port `vendor/afterburn/src/voxel/{kit,palette,mesh}.js`
→ `web/src/voxel/{kit,palette,mesh}.ts`" and requires the result to be
"behaviour-identical" so that "afterburn model code pasted here later must
compile with no edits". That contract requires reading the source.

What the container has mounted (from `/proc/mounts`):

- `/home/d/asciihack`         — the project (ro), overlay-writable via `.tigerteam`
- `/home/d/.agents-home`      — agent tools
- `/tigerteam-home`           — agent state (no `afterburn` here)

There is no `/home/d/afterburn`, `~/afterburn`, or any other path in the
filesystem containing `kit.js`/`VoxelBuilder`/`EMISSIVE_RANGE`/`GeoWriter`
(verified with `find /` and content grep). The claim "the user has
authorised copying from `~/afterburn` freely" is fine on the host but the
worker container is not given a mount for it.

The ticket's Context does list the API surface at a high level
(`VoxelBuilder.box/voxel/fill/…`, `PAL/MAT/FX`, `EMISSIVE_RANGE/GeoWriter/…`)
and the test names pin some behaviour, but that is not enough to hit
"byte-identical" or "no-edit pasteability":

- `makeRng`, `noise3`, `fbm3` — the seeded-RNG algorithm and the
  noise/fbm formulas are not specified. Different implementations will
  produce different values, so a model authored against afterburn's
  `builder.noise(...)`/`builder.fbm(...)` won't lay voxels identically.
- `transforms nest innermost-first: at() around bothX() mirrors about the
  offset` — the order semantics are clear, but the ticket does not spell
  out what `stamp`, `part`, `root`, `anchor`, `light` take as arguments.
- `GeoWriter` / vertex layout — "packs roughness, metalness,
  emissive/EMISSIVE_RANGE and the fx+flag byte" is only enough to hint at
  a 24 B/vertex encoding (`docs/gpu.md` §2); the byte offsets,
  quantisation and normalisation aren't stated.
- `PAL`, `MAT`, `FX` tables — the actual palette entries, material
  presets and fx codes are the *content* of `palette.js`, not derivable.

### Options

1. **PM mounts `/home/d/afterburn` into the worker container** (add it to
   `[workers]` mounts in `tigerteam.toml`, or via docker `-v`), then
   requeue T-0036. This is what the ticket's wording implies was intended.
2. **PM pastes the three source files into the ticket's Context** (or
   inline in the worktree, e.g. under `references/afterburn-voxel/`)
   before the next claim. Only ~520 lines total.
3. **PM re-scopes T-0036 as "voxel-kit skeleton from spec"**, dropping the
   "behaviour-identical / paste-compatible" requirement, so a worker can
   invent the RNG/noise/tables. This trades a real port for a placeholder
   and will silently diverge from any afterburn model code — probably not
   what the wave wants.

### Recommendation

Option 1 (mount `~/afterburn` into workers). It matches the ticket's
premise, keeps the copy truly byte-preserving (which is easy to verify
later with `diff`), and unblocks the rest of `docs/gpu.md` cheaply. No
code changed on this attempt — the worktree is clean.
