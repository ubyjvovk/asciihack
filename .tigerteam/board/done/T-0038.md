## Goal
Port the one node material every voxel in the scene uses, and replace the
sibling project's outdoor weather moods with a table of **dungeon** moods plus
the `Atmosphere` rig that blends between them. This is what gives the port its
wet stone, its torch flicker and its colour.

## Context
- **The sources are vendored in-repo at `vendor/afterburn/` (read-only).**
  `~/afterburn` itself is **not** visible inside the worker container —
  read the vendored copy, and diff your port against it before you hand
  off. A port written from a description instead of the source is not a
  port (this cost T-0037 an attempt).
- **Read first**: `docs/gpu.md` §5 (the lighting model for a dungeon) and §4,
  then `vendor/afterburn/src/render/materials.js` (115 lines) and `moods.js` (281).
  Copying from `~/afterburn` is authorised.
- `materials.ts` = afterburn's `createVoxelMaterial()` and the shared `W`
  uniform block, ported as-is **except**: drop the "Crystal Hollow" `aoNode`
  special case (it is a place in their world, not ours) and drop `hollowAO`
  from `W`. Keep wetness/puddles darkening and roughness, the stone water
  film, the blocky puddle noise, the emissive fx (`flicker`/`pulse`/
  `twinkle`), `lampGain`, `glow`, and the `sway` vertex option. Keep
  `fxByte()` and the `FLAG_*`/`FX_*` constants. Import `EMISSIVE_RANGE` from
  `../voxel/mesh.js` (landed by T-0036).
- `moods.ts` = the `Atmosphere` machinery from afterburn's `moods.js` (build
  the lights, apply a mood record, blend between two over N seconds, write the
  `look` uniforms and `W`) but with **no sky, no stars, no sun disc** — a
  dungeon has none. The mood record shape is:
  ```ts
  interface Mood {
    key:  { color: number; intensity: number };   // the dominant light's colour/strength
    fill: { sky: number; ground: number; intensity: number };  // hemisphere fill
    fog:  { color: number; density: number };
    weather: { wetness: number; puddles: number; wind: number };
    look: Partial<LookValues>;   // the pipeline uniforms this mood overrides
    glow: number; lampGain: number;
  }
  ```
- **Palette.** `web/src/voxel/palette.ts` (landed by T-0036) already carries
  everything a dungeon needs — use the keys, do not invent hexes:
  `basalt0..3` wet rock, `slate0..2` dry rock, `moss0..2`/`lichen`,
  `scorch0..2`/`ember`, `lamp` `0xffb060` and `fire` `0xff8a3c` for
  practical lights, `water` `0x1c3a40`, `mud`, `black`. Read
  `vendor/afterburn/docs/ART_BIBLE.md` §3 (palette) and §5 (how a mood is
  described) first — §5's table is the register these records are written in.
- **The mood table is specified — implement exactly these five ids**, tuning
  numbers within the stated intent (the PM eyeballs the result and will send
  a tuning ticket):
  | id | intent |
  |---|---|
  | `torchlit` | the default lit room: warm key `PAL.lamp` (`0xffb060`) at moderate strength, cool very dim fill, damp floor (`wetness` ≈ 0.5, `puddles` ≈ 0.25), fog `0x0b0d10` around 0.10, warm highlight tint, mild vignette |
  | `deep_dark` | corridors and unlit rooms: fill intensity 0, the hero lantern is the only light, fog roughly double `torchlit`, strong vignette, low saturation |
  | `flooded` | `wetness` 1.0, `puddles` 1.0, high `ssrIntensity`, cool teal shadow tint |
  | `lava` | hot key `PAL.ember` (`0xff6a2a`) from below, no wetness, high `bloomStrength`, warm saturated grade |
  | `ice` | cold key `0xbfe4ff`, pale high-key grade, low `grain`, `wetness` ≈ 0.3 with very low roughness |
- Blending must be a **pure exported function** so it is testable without a
  GPU: `export function blendMoods(a: Mood, b: Mood, t: number): Mood`
  (linear in numbers, per-channel linear in colours, `t` clamped to `[0,1]`).
  `createAtmosphere(...)` is the impure rig on top: `.set(id)`,
  `.blendTo(id, seconds)`, `.update(dtSeconds)` writing into the `look`
  uniforms from `pipeline.ts` (T-0037 may not have landed — do **not** import
  from `web/src/gpu/pipeline.ts`; take the look object as a constructor
  argument typed by a local structural interface and say so in the docs).
- TS strict, named exports, no `any`, relative imports end in `.js`, one-line
  JSDoc per export. `materials.ts` is browser-only (node materials, TSL).
  `tests/gpu-moods.test.ts` is compiled by the root tsconfig with **no DOM
  lib** — so keep `blendMoods`, the `MOODS` table and `fxByte` in modules the
  test can import without pulling in `three/webgpu`: put the pure mood data
  and `blendMoods` at the top of `moods.ts` and make sure importing it does
  not evaluate a TSL graph. If that forces a small split, say so in the docs.
