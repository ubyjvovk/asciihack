## Goal
`docs/gpu.md` §7 parks the ortho view on the legacy WebGL renderer while the
first-person view moves to the GPU path. Finish the job: the 3/4 overhead
camera and the cutaway that keeps the hero visible behind walls must work on
the GPU scene too, so both views share one look.

## Context
- **The sources are vendored in-repo at `vendor/afterburn/` (read-only).**
- **`GpuPath` lives in `web/src/gl/gl-viewport.ts`**; `web/src/gpu/path.ts`
  holds only the pure decision helpers and is **not** in scope. Put the pure
  parts of this ticket in `web/src/gpu/ortho.ts` so the tests can reach them
  without a renderer.
- The GPU dungeon already keeps its ceiling in a separate `ceiling` group on
  `DungeonScene.root` precisely so the overhead camera can hide it
  (`docs/gpu.md` §4) — use it; do not rebuild geometry for the ortho view.
- Read `docs/gpu.md` §6–§7, `docs/gpu-compose.md`, and today's implementation:
  `web/src/gl/ortho-camera.ts` (`placeOrthoCamera`, `cutawayCellsFor`) and the
  `applyCutaway` path in `web/src/gl/gl-viewport.ts`. Reuse
  `ortho-camera.ts` — the frustum and cutaway-set maths are already right and
  unit-tested; this ticket is about applying them to the GPU scene.
- The cutaway currently hides wall instances and draws translucent ghost
  cubes. On the GPU scene the level is **one merged geometry**, so instance
  hiding is not available. Decide between (a) a second, small "ghost" mesh
  built from the cutaway cells each time the set changes, or (b) a clip
  volume in the material driven by the hero cell. Pick one, state why in the
  docs, and keep it under the §8 budget.
- DOF focus must track the ortho camera (afterburn's `focus`/`focusRange`
  are in metres from the camera, and the ortho camera sits much further out
  than the first-person one) — otherwise the whole board renders out of focus.

### Notes for the reviewer

- **`docs/gpu.md` §7 is now stale.** That paragraph says the cutaway
  keeps riding the legacy path "until a later ticket ports the cutaway
  to the GPU scene" — this ticket is that ticket. `docs/gpu.md` is
  PM-owned per PROTOCOL §6, so I did not edit it; the ~10-line rewrite
  can fold into your next `docs/gpu.md` edit. Suggested replacement:
  "`web/src/gl/scene-builder.ts` and its materials remain the fallback
  path (§3, §6). The ortho view now also runs through the ported GPU
  stack — see `docs/gpu-ortho.md` — but falls back to the legacy scene
  under `?gpu=off`, depth styles, or GPU-init failure like fps does."
- **Cutaway is a compromise on merged geometry.** The ghost mesh
  overlays a translucent tint on cutaway cells but cannot make the
  underlying merged wall geometry transparent, so the hero remains
  partially occluded when a wall sits exactly in front of it. Full
  transparency needs a clip volume in `materials.ts` (option b) — a
  follow-up ticket. This is documented and called out in
  `docs/gpu-ortho.md` §"What (a) does not deliver — and the follow-up".
  If the eyeball review shows the compromise is unacceptable, please
  raise it as the option-(b) ticket rather than reworking this one —
  option (a)'s pieces (ceiling hide, camera placement, DOF sync) all
  still stand under option (b).
- **Projection-matrix copy is the load-bearing trick.** `createPipeline`
  binds one camera at build time. To avoid a pipeline rebuild on every
  F3 toggle, ortho frames drive a dedicated `WG.OrthographicCamera`,
  then copy its `projectionMatrix` + `projectionMatrixInverse` +
  `position` + `quaternion` onto the pipeline's perspective camera.
  Nothing three-internal calls `updateProjectionMatrix()` per frame, so
  the override sticks. The fps branch's `lastView === 'ortho'` guard
  forces `updateProjectionMatrix()` on the way back so perspective is
  correctly re-derived on the F3-back frame. I could not verify at a
  live renderer that every TSL node (SSGI, SSR, TRAA, DOF) copes
  correctly with an ortho projection matrix on a `PerspectiveCamera`
  reference — it should (all read the matrix, not the fov/aspect
  fields), but PM eyeball is the truth.
- **Lantern reparented to scene.** Was `camera.add(lantern)`; now
  `scene.add(lantern)` with `lantern.position.set(pose.x, EYE_HEIGHT,
  pose.y)` every frame. Same world position in fps (this is not a
  regression); in ortho the light stays at the hero instead of riding
  the camera 40 cells out.
- **Out-of-scope things I noticed but did not touch.** The file header
  docstring in `web/src/gl/gl-viewport.ts` still describes the ortho
  cutaway as a legacy-only thing ("any wall within 2 cells in front of
  the hero is swapped for a translucent ghost cube") — the sentence is
  still correct for the legacy path (which is exactly what runs on
  `?gpu=off`) but no longer covers the whole story. Not touched
  because the edit is cosmetic and not on the acceptance list; happy to
  fold into a follow-up.
