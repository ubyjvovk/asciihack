## Goal
Empty air reads as cheap. Afterburn puts rain, spray and drifting motes in
front of the camera as a separate additive pass; port that machinery and give
the dungeon its own three: **drips** falling from the ceiling in wet rooms,
**dust motes** drifting in torchlight, and **embers** rising from a torch or
lava. It is the cheapest large gain in "does it feel like a place".

## Context
- **The source is vendored in-repo at `vendor/afterburn/src/render/weather.js`
  (read-only).** `~/afterburn` is not visible inside the worker container.
  Read it first, then `docs/gpu.md` §5–§6 and `docs/gpu-materials.md`.
- **`GpuPath` lives in `web/src/gl/gl-viewport.ts`**; `web/src/gpu/path.ts`
  holds only pure helpers and is not in scope. Keep the pure parts of this
  ticket in `web/src/gpu/weather.ts` so the tests can reach them.
- The **overlay pass already exists** in the ported pipeline: `createPipeline`
  takes an `overlay` scene and composites it additively *after* the lighting
  stack, precisely so transparent quads never pollute the G-buffer that SSGI
  and SSR read. Use it — do not add particles to the main scene.
- Drive intensity from the mood uniforms in `W` (`rain`, `wetness`, `glow`)
  and from the active mood id, so `flooded` drips hard, `deep_dark` is still
  and dusty, and `lava` throws embers.
- Keep it GPU-side and allocation-free per frame, the way the source does:
  one buffer of points with a position/seed attribute and a TSL `positionNode`
  that animates them from `time`, wrapped in a box around the camera. No
  per-frame JS particle loop.
- Budget: the overlay must cost under 1 ms at 640×360 on `high`.

### For the reviewer

- The mood → emitter mapping in `emitterTargets` is deliberately
  asymmetric: mood is a fence (a `deep_dark` corridor cannot rain no
  matter what `W.wetness` says), while `W` is a multiplicative scale on
  top. The two ticket-named tests pin both directions.
- One rework happened inline while writing the second test: my first
  invariant claim about `wrapAround` ("shift focus by delta shifts
  wrapped position by the same delta") was wrong — the wrap keeps
  particles fixed relative to the world lattice, so focus shifts produce
  world-position deltas of exactly 0 or `±2R`, never a fractional slide.
  The corrected invariant is what "wraps around the camera" actually
  means, and the fix caught a real understanding gap, not a code bug.
- Out-of-scope observations, none touched: the drip `focus.y` currently
  rides at `EYE_HEIGHT = 0.5` (the wrap volume ends up at `y ∈ [0.5,
  4.5]`), which anchors drips just above head height. If the PM's shot
  shows streaks reading as "from the sky" instead of "from the
  ceiling", the fix is passing `pose.y` as the y-focus in `GpuPath.render`
  — a one-line change but a `render`-loop tweak, so I did not make it
  speculatively.
