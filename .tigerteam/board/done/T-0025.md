## Goal
Sprites are going to be shaped by NetHack's own tile art. This ticket
delivers the data: (1) a generator that turns `nethack/win/share/
{monsters,objects,other}.txt` into a committed `src/render/tiles.json`
plus a lookup module, and (2) `hello.extra.monsters` / `hello.extra.objects`
from the bridge so the client can map a glyph's monster/object index to a
name, letter and size. Rendering is the next ticket (T-0026).

## Context
- `Tile` type: `src/model/types.ts` (PM-owned; `pixels` = one palette
  index per pixel, row-major, index 0 = transparent, `palette[0]` is the
  transparent colour).
- **Tile text format** (`nethack/win/share/monsters.txt`, `objects.txt`,
  `other.txt`): a palette header of lines `X = (r, g, b)` (the `.` entry
  `(71, 108, 108)` is the transparent background), then per tile a
  `# tile N (name)` line followed by `{`, 16 rows of 16 palette characters
  (indented), `}`. Other `#` lines are comments. Monster names look like
  `jackal,male` / `jackal,female`; object names `dagger` or
  `descr / name` (e.g. `vulgar polearm / partisan`, `emerald / polymorph
  control`); `other.txt` names are features (`stone`, `main walls
  vertical`, `branch staircase up`, …). 789 / 483 / 243 tiles.
- `scripts/gen-tiles.ts` (run with `npx tsx`): parses the three files
  (read from `nethack/` — the submodule must be populated:
  `bash scripts/nethack-src.sh`) into `src/render/tiles.json`:
  ```json
  { "palette": [[71,108,108],[0,0,0],…],
    "monsters": { "jackal": {"m": "<256 palette-index chars>", "f": "…"} },
    "objects":  { "dagger": "…", "partisan": "…" },
    "objectsByDescr": { "vulgar polearm": "…" },
    "other":    { "stone": "…", … } }
  ```
  Pixel strings are 256 characters of palette index encoded as base-64
  digits or similar compact ASCII (document it); the palette is shared
  (all three files use the same table — verify, fail loudly if not).
  Names are lower-cased. Commit the JSON (≈ 400 KB; mark it
  `linguist-generated` in `.gitattributes`). Do not edit `nethack/`.
- `src/render/tiles.ts`: `loadTiles(): TileSet` (parses the JSON once,
  lazily), `monsterTile(set, name, female?: boolean): Tile | null` (male
  variant by default, female when asked, fall back to the other),
  `objectTile(set, name, descr?): Tile | null` (name first, then descr),
  `otherTile(set, name)`. Decoding yields `Tile` objects; cache them.
- **Bridge**: in `print_hello`, add `extra.monsters` = for `i` in
  `0 … NUMMONS−1`: `{"name": mons[i].pmnames[NEUTRAL] ?? MALE,
  "male": pmnames[MALE] or null, "female": pmnames[FEMALE] or null,
  "letter": def_monsyms[mons[i].mlet].sym as a 1-char string,
  "size": mons[i].msize, "color": mons[i].mcolor}`, and `extra.objects`
  = for `i` in `0 … NUM_OBJECTS−1`: `{"name": OBJ_NAME(objects[i]) or
  null, "descr": OBJ_DESCR(objects[i]) or null, "cls": the class letter
  (`def_oc_syms[objects[i].oc_class].sym`)}`. Names must be JSON-escaped
  with the existing `json_str`. Update `docs/bridge.md` (hello section).
  Grep `include/permonst.h` (`pmnames[NUM_MGENDERS]`, gender indices in
  `include/monsym.h`/`hack.h`: `MALE`, `FEMALE`, `NEUTRAL`), `include/objclass.h`
  (`OBJ_NAME`, `OBJ_DESCR`, `NUM_OBJECTS`), `include/monst.h`/`monsym.h`
  (`def_monsyms`, `def_oc_syms`).
- Smoke: `scripts/bridge-smoke.ts` asserts `hello.extra.monsters` has an
  entry with `name === "jackal"`, `letter === "d"`, `size === 1`
  (MZ_SMALL), and `hello.extra.objects` has `name === "dagger"`;
  `tests/bridge.test.ts` the same under its `skipIf`.
