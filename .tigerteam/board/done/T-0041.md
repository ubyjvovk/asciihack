## Goal
The ported pipeline's SSR pass **silently produces nothing on three's WebGL2
fallback backend** — its fragment shader fails to link. That backend is not a
corner case: it is the path headless verification runs on, and the fallback
for anyone without WebGPU. Gate around the bug so SSR works on both backends.

## Context
- **Read `docs/gpu.md` §3** — the bug, the evidence and the decided rule are
  written there. Short version: `SSRNode.js` builds its step count as
  `trunc(…).max( int( 1 ) )`, which three's GLSL backend emits as
  `max( int( trunc( … ) ), 1.0 )`. GLSL ES 3.0 rejects the `int`/`float`
  mismatch, the program never links, and the pass contributes nothing while
  the console fills with `INVALID_OPERATION`. WGSL coerces it, so WebGPU is
  fine. Reproduced and isolated with
  `/gpu-probe.html?backend=webgl2&stack=ssr&stochastic=0` (fails) vs
  `&stochastic=1` (renders in 37.5 ms).
- **The rule, already decided — implement exactly this.** In
  `createPipeline`'s SSR branch, pass `stochastic: true` when the renderer is
  on the **WebGL2** backend and `stochastic: false` (afterburn's setting) when
  it is on **WebGPU**. Stochastic SSR is noisier and expects a temporal
  denoiser downstream; every tier that enables SSR already runs TRAA, so that
  condition holds. Note in the code and the docs that
  `reflectNonMetals` is only consulted on the non-stochastic path.
- Detect the backend the same way `renderer.ts` does
  (`renderer.backend?.isWebGPUBackend === true`) rather than re-probing
  `navigator.gpu` — the renderer may have been forced to WebGL2 with
  `forceWebGL`.
- Keep it **one line of branching** with a comment naming the three version,
  so it can be deleted when three fixes `SSRNode.js` (the fix upstream is
  `.max( int( 1 ) )` → `.max( 1 )`).
- Expose the choice as a pure, testable function —
  `export function ssrStochastic(isWebGPU: boolean): boolean` — and have the
  SSR branch call it. Do not change anything else about the pass
  (`maxDistance`, `thickness`, `quality`, `intensity`, `resolutionScale` stay
  as ported).
