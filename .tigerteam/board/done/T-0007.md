## Goal
The point of the project: play NetHack in the terminal with the dungeon
rendered first-person (raycaster) or isometric (ortho), switching with
`F2`/`F3`, with a classic-map minimap in the corner, arrow-key facing
controls that translate to NetHack moves, and the render themes. After
this ticket `npm start` (default `--mode=fps`) is the game.

## Context
- Read `docs/architecture.md` §5, §6.3, §6.4, §7 and `docs/ui.md` (the
  `App` loop and the mode interface from T-0004: `paintViewport(grid,
  rect)`, `handleKey(e)`, `onEnter/onLeave`; the fallback banner for
  fps/ortho is what you replace). Renderers: `renderFirstPerson`
  (`src/render/raycast.ts`, docs/render.md), `renderOrtho`
  (`src/render/ortho.ts`), `quantizeInto` with `theme`
  (`src/render/ascii.ts`, docs/terminal.md "Themes"). Session API:
  `docs/engine.md` (`session.map`, `session.hero`, `session.pending`,
  `session.answer`).
- `src/ui/view3d.ts` — shared plumbing, pure and tested:
  `spritesFromMap(map: LevelView, hero): Sprite[]` (every cell whose `top`
  glyph is not `cmap`/`unexplored`/`nothing`, hero cell excluded for fps
  and **included** as `@` for ortho — take an `includeHero` flag; colour =
  `clrToRgb(top.color) / 255`); `FACINGS` (8 compass directions in
  clockwise order from north, each with its yaw and vi-key `k u l n j b h y`);
  `turn(facing, ±1)`; `opposite(facing)`; `strafe(facing, ±1)` (±2 steps =
  90°); `poseFor(hero, yawRad): Pose` (hero cell centre); `blitGrid(src,
  dst, rect)` copying a quantized `ScreenGrid` into a rectangle of the
  App's grid; and a `Viewport3D` helper owning one `FrameBuffer` +
  `ScreenGrid` sized to the rect (reallocated on size change) with
  `render(fn: (fb) => void, theme): ScreenGrid`.
- **Turn animation**: `App` gains `requestFrame()`; a mode may return
  `true` from a new optional `tick(nowMs): boolean` to ask for another
  frame; while any tick returns true the App repaints at ≤ 30 fps
  (`setTimeout`, no busy loop). The fps mode interpolates its yaw toward
  the facing's yaw over 120 ms on a turn (`Left`/`Right`), so the world
  swings instead of snapping. Ortho has no camera rotation.
- **Controls (§6.4)**, only in fps/ortho and only when NetHack is waiting
  for a key (`session.pending` is a key request; otherwise keys go to the
  overlay/prompt exactly as classic mode does):
  - `Left`/`Right`: turn 45° — consumed, never sent to NetHack.
  - `Up`: send the vi-key of the facing; `Down`: the opposite facing's key
    (NetHack walks backwards). `Shift+Left/Right`: strafe (facing ±90°).
  - A vi-key (`hjklyubn`, and their capitals) or number-pad digit typed
    directly is sent unchanged **and** sets the facing to that direction.
  - Everything else passes through unchanged. `F1/F2/F3` still switch
    modes; `F4` toggles the minimap; `F5` cycles the theme
    (cyber → gloom → solarized → amber); `Ctrl+L` redraws.
  - In ortho mode `Left`/`Right`/`Up`/`Down` are plain NetHack moves
    (west/east/north/south) — there is no facing.
- **Minimap** (`src/ui/minimap.ts`): a 40×11 window of the classic map
  centred on the hero (clamped to the map bounds), drawn top-right over
  the viewport with a one-cell border of `-`/`|` in dim grey, the hero
  cell inverse-video, glyph colours from `clrToRgb`; unexplored = space.
  Shown by default in fps/ortho; `F4` hides it.
- Layout stays §6.3: row 0 messages, viewport rows 1..H−3, two status
  rows. The viewport is the whole width. Terminal ≥ 80×24 required
  (the App already enforces it).
- `src/cli.ts`: `--mode=fps|ortho|classic` (default `fps`), `--theme=`,
  `--no-minimap`. README: update the key table and the mode description;
  `docs/ui.md`: the tick/requestFrame protocol, facing rules, minimap.
- Tests use the fake `TermIO` and the fixture-driven session from
  T-0004's tests (`tests/fixtures/bridge/start.jsonl`); render checks
  look for structure, not exact pixels: after replaying `start.jsonl` in
  fps mode the viewport rows contain ramp glyphs (not all spaces) and
  the minimap rectangle contains the hero's `@`; in ortho mode the
  viewport contains the hero sprite's `@` overlay.
