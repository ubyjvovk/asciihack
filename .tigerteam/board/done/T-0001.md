## Goal
Build NetHack 5.0 from the `nethack/` git submodule without touching the
submodule, in two variants: `tty` (the plain console game, so the user can
play vanilla NetHack from this repo and we have a known-good baseline) and
`lib` (`libnethack.a` + headers + runtime "playground" dir, which the C
bridge of T-0002 links against). One idempotent script, one doc.

## Context
- Read `docs/architecture.md` §2 (out-of-tree rule), §3.1 (what `WANT_LIBNH=1`
  produces), §8 (`build/` layout), §9.
- NetHack's own instructions: `nethack/sys/libnh/README.md` (lib + the
  `setup.sh hints/<file>` ritual), `nethack/sys/unix/Install.unx`,
  `nethack/sys/unix/hints/linux.500` (the hints file to use; the
  `WANT_LIBNH` block is around line 483) and
  `nethack/sys/unix/hints/include/dirs-perms.500` (install dirs: `HACKDIR`,
  `INSTDIR`, `VARDIR` are `?=` so command-line `make VAR=...` overrides
  them; the default is a `playground/` dir under the source root).
- Lua: NetHack needs Lua 5.4.8 sources in `lib/`. `make fetch-lua` (see
  `nethack/sys/unix/Makefile.top`, targets `fetch-Lua`, `fetch-lua-http`)
  downloads them with checksum verification. Cache the tarball in
  `build/cache/` so the second build never needs the network.
- The worker container has gcc 12, make, ncurses-dev, git, curl, network.
  There is no `rsync` guarantee — copy the tree with `tar` or `cp -a`.
- Submodule in a worktree: `git worktree add` leaves `nethack/` empty.
  `scripts/nethack-src.sh` must populate it: if `nethack/include/hack.h`
  is missing, run `git submodule update --init -- nethack`, passing
  `--reference "$(git rev-parse --git-common-dir)/modules/nethack"` when
  that directory exists (it does in linked worktrees — it is the main
  checkout's copy, so no network clone is needed). Print the submodule
  commit at the end.
- `.gitignore` already ignores `build/`; add anything else the build
  creates outside `build/` (there should be nothing — that is the point).

## Acceptance criteria
- [ ] `bash scripts/nethack-src.sh` populates `nethack/` in a fresh worktree
      and is a no-op when it is already populated.
- [ ] `bash scripts/nethack-build.sh tty` copies the submodule to
      `build/nethack/tty/src-tree/` (skipped when the stamp file matches the
      current submodule commit), runs `setup.sh hints/linux.500`, fetches or
      unpacks Lua from `build/cache/lua-5.4.8.tar.gz`, builds and installs
      into `build/nethack/tty/playground/` so that
      `build/nethack/tty/playground/nethack --version` prints a line
      containing `NetHack Version 5.0`.
- [ ] `bash scripts/nethack-play.sh` runs that binary with `HACKDIR` /
      `NETHACKDIR` pointing at `build/nethack/tty/playground` (arguments
      pass through), i.e. the user can play vanilla NetHack in the console.
- [ ] `bash scripts/nethack-build.sh lib` produces, under `build/nethack/lib/`:
      `libnethack.a`, `liblua.a` (copied from wherever the tree builds them),
      `include/` (a copy of `nethack/include/` **plus** the generated headers
      from the build, e.g. `date.h`, `pm.h`, `onames.h`, `nhlua.h` — whatever
      `make` generates), `cflags.txt` (one line: the exact `CFLAGS` the tree
      used to compile `src/*.c` for this variant, extracted from the
      generated `src/Makefile` — the bridge must compile with the same
      flags), and `playground/` (the runtime dir: `nhdat`, `sysconf`,
      `symbols`, and empty `record`/`perm`/`logfile`/`xlogfile`/`livelog`
      files, plus `save/` — mirror what the tty install puts there).
- [ ] `nm build/nethack/lib/libnethack.a | grep -E " T (nhmain|shim_graphics_set_callback)$" | wc -l`
      prints `2`.
- [ ] Running `bash scripts/nethack-build.sh lib` a second time finishes in
      under 30 s and does not touch the network (stamp + cache).
- [ ] `git status --porcelain nethack` is empty after both builds (the
      submodule is untouched) and no files appear outside `build/` and the
      scope.
- [ ] `bash .tigerteam/scripts/run-tests.sh` exits 0 (unchanged suite).
- [ ] `docs/nethack-build.md` documents: the two variants and their output
      paths, the Lua cache, the stamp/idempotency rule, the worktree
      submodule trick, and how to play the console game.
- [ ] No files changed outside scope

### Notes for the reviewer
- NetHack 5.0 does **not** generate `pm.h`/`onames.h` (the ticket's example list) — `make` only generates `date.h` and `nhlua.h`. I copy the whole `include/` tree, so `build/nethack/lib/include/` automatically contains whatever `make` generates plus the source headers.
- The lib tree builds `src/libnh.a` (not `libnethack.a`); the script renames it to `libnethack.a` on collection. Verified the required symbols are present.
- With `WANT_LIBNH=1` the game binary is disabled, so the `lua_support` target (which normally generates `nhlua.h`) never fires; the lib variant runs `make WANT_LIBNH=1 lua_support` first.
- `HACKDIR`/`INSTDIR`/`VARDIR` are overridden on the `make` command line (they are `?=` in `dirs-perms.500`) to keep the playground **outside** `src-tree/` at `build/nethack/<variant>/playground/`, as the acceptance criteria specify. Absolute paths are used because make resolves them relative to the src-tree cwd.
- `cflags.txt` is extracted by feeding a one-line `printflags` target to make via `-f /dev/stdin` with `WANT_LIBNH=1`, so it is the exact expanded flags including `-DSHIM_GRAPHICS -DNOTTYGRAPHICS -DNOSHELL -DLIBNH -fpic` and `-DDEFAULT_WINDOW_SYS="shim"`.
- I could not eyeball an actual rendered game frame (interactive tty); verification was via `--version`/golden ASCII output per AGENTS.md. The PM should run `bash scripts/nethack-build.sh tty` + `nethack-play.sh` for the eyeball check.
- Out-of-scope, not touched: the `bridge` variant (T-0002) and anything under `nethack/`.
