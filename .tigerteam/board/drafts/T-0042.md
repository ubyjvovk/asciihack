## Goal
The GPU dungeon is currently empty of life: `DungeonScene` builds terrain
only, so monsters, items and the hero vanish when the GPU path is active.
Put them back, lit by the ported stack rather than pasted on top of it.

## Context
- **The sources are vendored in-repo at `vendor/afterburn/` (read-only).**
  `~/afterburn` is not visible inside the worker container.
- Read `docs/gpu.md` §4–§6, `docs/gpu-dungeon.md`, and how the legacy path
  does it today: `web/src/gl/gl-viewport.ts` (`spriteMaterialFor`,
  `tileToTexture`) and `web/src/gl/scene-builder.ts` (`updateSprites`).
  `Sprite` (`src/model/types.ts`) carries `x`, `y`, `ch`, `rgb`, `cls`,
  `height` (0.3 tiny … 1.3 gigantic) and an optional 16×16 `tile`.
- **The decision: billboards, not voxel models.** NetHack has ~400 monsters;
  hand-building voxel models is a different project. Each sprite is a camera-
  facing quad carrying the tile art as a `NearestFilter` texture, drawn with
  a **node material** so it takes the scene's lighting: alpha-tested (not
  blended, so it writes depth and SSR/SSGI see it), `MeshStandardNodeMaterial`
  with `colorNode` = the tile texture × the sprite tint, roughness 0.85,
  and a small emissive for `cls` values that glow.
- Billboard about the **Y axis only** (yaw toward the camera, never pitch),
  so a monster stays standing when the ortho camera looks down at it.
- Stand the quad on the floor: height = `sprite.height ?? 0.7` cells, width
  from the tile's aspect, base at `y = 0`, centre at the cell centre.
- Pool the quads: one `InstancedMesh`-free `Mesh` per live sprite is fine at
  NetHack's counts (≤ ~40 on screen), but reuse the objects across frames and
  cache textures/materials per tile key exactly as the legacy path does —
  rebuilding a `CanvasTexture` per frame is the bug that ticket T-0031 hit.
- The hero: the legacy path draws an `@` glyph sprite; keep that behaviour and
  the same `HERO_SPRITE_HEIGHT`.
