## Goal
NetHack distinguishes lit room floor (`S_room`) from remembered dark floor
(`S_darkroom`) and lit corridors (`S_litcorr`) from dark ones (`S_corr`).
Carry that into the model and the two 3D renderers so a dark room reads
as dark (you remember its shape, not its light) and a lit one as lit —
a real gameplay cue for free.

## Context
- `src/model/types.ts` (PM-owned): `MapCell.lit?: boolean` exists (added
  by the PM). `src/engine/glyphs.ts` (`classifyCmap`), `src/engine/session.ts`
  (`print_glyph` handling, §4.2 rules), `docs/render.md` (levels).
- Engine: when a `cmap` glyph sets a cell's terrain, also set `lit`:
  `S_room`, `S_litcorr` → `true`; `S_darkroom`, `S_corr` → `false`; other
  kinds leave it `undefined`. A monster/object glyph on a cell does not
  change `lit`. Export `litOf(symIdx, S): boolean | undefined` from
  `glyphs.ts` and use it in the session.
- Raycaster (`src/render/raycast.ts` floor pass): floor cells with
  `lit === false` use the base colour ×0.45 and no flagstone highlight
  (stones still vary but darker); corridors already dark stay as they
  are unless `lit === true` (then ×1.4). Walls are unaffected (they are
  lit by the hero's lantern in the fiction). Grid lines keep their
  absolute level, so dark rooms still show perspective.
- Ortho (`src/render/ortho.ts` floor pass): same ×0.45 for unlit floor
  tiles.
- Fixture: extend `levelFromAscii` (tests/fixtures/levels.ts is not in
  scope — instead build the test level in the test with `cellAt`-style
  overrides, or add a `lit` map parameter to your own helper inside the
  test file) so a test can mark a region dark.
- Regenerate the goldens only if they change (the `ROOM` fixture has no
  `lit` info, so they should not).
