## Goal
`renderFirstPerson(level, pose, sprites, fb, opts)` — the Wolfenstein-style
grid raycaster that turns the remembered NetHack map into a first-person
scene in a `FrameBuffer`, exactly as `docs/architecture.md` §5.2 specifies.
Pure and deterministic so it can be golden-tested in node.

## Context
- Read `docs/architecture.md` §5.1, §5.2, §7 (coordinates: `x` east,
  `y` south, yaw 0 = north, +π/2 = east clockwise) and §10. Types are
  PM-owned in `src/model/types.ts`: `LevelView`, `Pose`, `Sprite`,
  `FrameBuffer`, `makeFrameBuffer`, `isSolid`, `CellKind`.
- `tests/fixtures/levels.ts`: `levelFromAscii(rows: string[]): LevelView`
  building a `LevelView` from a legend (`#` wall, `.` floor, `+` closed
  door, `|`/`-` also wall, `'` open door, `D` doorway, `~` water, `T` tree,
  `>`/`<` stairs, space = unexplored, `%` corridor). Export a `ROOM` (a
  12×8 room with a door on the east wall and a corridor beyond) and an
  `L_SHAPED` level for tests.
- `RaycastOptions {fovDeg?: number (70), maxDepth?: number (24),
  cellAspect?: number (2 — cell height / width), fogK?: number (0.18)}`.
- Colours by kind (linear RGB 0..1, before exposure): wall `[0.55, 0.53,
  0.50]`, door_closed `[0.55, 0.35, 0.15]`, door_open/doorway frame `[0.45,
  0.30, 0.12]`, tree `[0.15, 0.45, 0.15]`, bars `[0.3, 0.6, 0.65]`,
  stone/unexplored `[0.06, 0.06, 0.07]`; floor `[0.40, 0.37, 0.33]`,
  corridor `[0.28, 0.22, 0.16]`, water `[0.10, 0.25, 0.60]`, lava `[0.85,
  0.35, 0.05]`, ice `[0.55, 0.75, 0.85]`, stairs_up/stairs_down `[0.85,
  0.85, 0.40]`, altar `[0.7, 0.7, 0.75]`, fountain `[0.3, 0.5, 0.9]`,
  trap `[0.6, 0.2, 0.6]`, anything else floor-coloured. Ceiling: `[0.03,
  0.03, 0.04]` fading to black at the top row. Export the table as
  `KIND_COLORS` so the ortho renderer (later) reuses it.
- Depth plane: perpendicular wall distance for wall cells, floor-row
  distance for floor/ceiling cells; `Infinity` never appears inside
  `maxDepth` except where the ray leaves the map.
- Sprites: sort far to near, project, clip to the wall depth per column,
  fill `overlayCh`/`overlayRgb` in the rectangle (§5.2); a sprite exactly
  on the camera cell is skipped.
- Golden test: render `ROOM` from the centre facing east at 80×24 into a
  buffer, quantize it with a *test-local* 10-glyph ramp (`" .:-=+*#%@"`
  over `max(r,g,b)` — do **not** import `src/render/ascii.ts`, it is being
  written in parallel) and compare against `tests/raycast-golden.txt`
  (commit the golden; print a diff on failure). Regenerate with
  `UPDATE_GOLDEN=1`.

## Acceptance criteria
- [ ] `bash .tigerteam/scripts/run-tests.sh tests/raycast.test.ts` exits 0
- [ ] New tests cover: a wall straight ahead at distance 3 lands at the
      expected screen height (±1 row) and column range; facing a wall at
      45° gives the E/W face shade (70 %) on one side; `unexplored` stops
      rays; a closed door is solid and door-coloured, an open door is not
      solid; the floor row under a `water` cell is blue-dominant; a sprite
      behind a wall is not drawn, a sprite in view writes its `ch` into
      `overlayCh` with more cells when nearer; yaw 0 looks north (the
      north wall of `ROOM` fills the view), +π/2 looks east; two renders
      with the same input are byte-identical; the golden matches;
      rendering 200×60 takes under 8 ms on average over 20 runs (log the
      number, assert < 40 ms so CI noise never fails it).
- [ ] Every exported function has a JSDoc line; `docs/render.md` describes
      the algorithm, the colour table, the aspect correction, and the
      golden workflow.
- [ ] No files changed outside scope
