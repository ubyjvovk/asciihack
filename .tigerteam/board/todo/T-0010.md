## Goal
Three small correctness fixes in `bridge/nh-bridge.c` found in PM review
(listed in `docs/architecture.md` §3.3 "hardening backlog"). No behaviour
change on x86-64 today; they remove undefined behaviour and an
out-of-bounds read.

## Context
- `bridge/nh-bridge.c`, function `handle_callback`. The shim's argument
  formats are in `nethack/win/shim/winshim.c` (`DECLCB`/`VDECLCB` lines).
- Build and test: `bash scripts/nethack-build.sh bridge` (compiles with
  `-Wall -Wextra -Werror`, runs `make -C bridge test`), then
  `npx tsx scripts/bridge-smoke.ts` must still print the hero line.

## Acceptance criteria
- [ ] `shim_start_menu`: `mbehavior` is declared `unsigned long` in the
      shim; read it with `va_arg(ap, unsigned long)` (not `int`) and print
      it with `%lu`. Fix the misleading comment.
- [ ] Unknown-call fallback (bottom of `handle_callback`): never
      `memset(ret_ptr, 0, sizeof(void *))` — the return slot may be a 1-byte
      `char`/`boolean` or a 2-byte `short`. Zero exactly the width named
      by `fmt[0]`: `c`/`b`/`0` → 1 byte, `2` → `short`, `i` → `int`,
      `s`/`p` → pointer, `v` → nothing.
- [ ] `shim_select_menu`: guard `w < 0 || w >= MAX_WIN` before touching
      `g_menus[w]` (treat as "no items": `ret = 0`, `*menu_list = NULL`).
- [ ] `bash scripts/nethack-build.sh bridge` succeeds and
      `npx tsx scripts/bridge-smoke.ts` exits 0;
      `bash .tigerteam/scripts/run-tests.sh` exits 0.
- [ ] `docs/bridge.md`: remove the corresponding lines from its known-limits
      list if present; one sentence noting the fallback zeroes by `fmt`.
- [ ] No files changed outside scope

## Out of scope
Any protocol change, any new call handling, anything in `reply.c`.
