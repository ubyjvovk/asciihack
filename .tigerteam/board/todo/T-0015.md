## Goal
Three small things the PM saw while playing classic mode (T-0004) that
make the game feel off; none blocks play, all are cheap.

## Context
- **yn default shows as `[]`.** `YnOverlay` (src/ui/overlays.ts ~265)
  prints `` [${String.fromCharCode(def)}] `` whenever `def` is non-zero;
  "Really save?" arrived with a control-character default so the box
  read `Really save? yn []`. Print the default only when it is a
  printable ASCII character (0x21–0x7e), and format the prompt like
  tty does: `Really save? [yn] (n)`.
- **Menu cancel sends "nothing selected", not "cancelled".**
  `NethackSession.answer({kind:'menu', selected: []})` serialises `ret 0`;
  the protocol (`docs/architecture.md` §3.3 `select_menu`) has `ret −1`
  for a cancelled menu and NetHack behaves differently for the two on
  some prompts. Add `{kind:'menu', cancelled: true}` to the `Answer`
  union → `{id, ret: -1}` (no `selected`), and make `MenuOverlay` send it
  on ESC (Enter with nothing picked stays `ret 0`). Document both in
  `docs/engine.md`.
- **Final `--More--` after the bridge has gone.** After `S`/`y` NetHack
  prints "Saving..." with a blocking message display, then exits; the
  App waits for a keypress on a `--More--` whose game is already over.
  When the session emits `exit` while a `display`/`more` overlay is the
  only thing pending, dismiss it and leave immediately (keep the pause
  when the bridge is still alive — death messages and DYWYPI need it).
  Also make sure the process exits within 500 ms of `exit` even if some
  timer/stdin listener is still registered (`tty.ts` leave path).
