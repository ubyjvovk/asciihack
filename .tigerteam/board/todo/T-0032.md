## Goal
`F3` in the browser shows the same three.js dungeon from a fixed 3/4
overhead camera (the Diablo/Fallout view), rendered through the same
AsciiCity style shaders, with the hero drawn and walls in front of the
hero cut away.

## Context
- `docs/web.md` (T-0031's viewport: `GlViewport` owns renderer / scene /
  camera / `StyleRenderer`; `render(session, pose, sprites, nowMs)`),
  `web/src/asciicity/render/scene.ts` (`makeCamera` is perspective; add an
  orthographic one here, do not edit the vendored file), the terminal
  ortho conventions in `docs/render.md` (north up-right on screen).
- `web/src/gl/ortho-camera.ts` (pure maths + a thin three.js wrapper):
  `THREE.OrthographicCamera` looking at the hero's cell centre from
  azimuth 225° (so north is up-right and east down-right, like the
  terminal ortho) and elevation 35°, `up = +y`; the view height in cells
  is `rows / (3.5 · k)`-equivalent: choose the frustum so the hero sprite
  is about 1/7 of the viewport height (`viewHeight = 7 · heroHeight`
  world units), keep aspect from cols/rows and the cell aspect.
  `placeOrthoCamera(cam, hero, cols, rows, cellAspect)` is the pure part
  (positions/frustum as numbers) so it can be tested without WebGL.
- Hero sprite: in fps the hero is not drawn; in ortho add a `Sprite` for
  the hero at `session.hero` with the tile of the player's role when
  `tiles.json` has it (monster tiles include the player roles:
  `archeologist`, `barbarian`, …, `valkyrie`, `wizard`; the role is the
  last word of the status title before " the ", e.g. "Pmtest the
  Rhizotomist" → look up the rank title is unreliable, so use
  `session.status` `BL_TITLE` only as a fallback and prefer the role from
  `NETHACKOPTIONS` if the client passed one; else a generated `@`
  canvas texture), `height 0.7`.
- Cutaway: wall cubes whose cell is within 2 cells in front of the hero
  (greater `x + y`, `|dx| ≤ 2`, `|dy| ≤ 2` — the terminal rule) use a
  second material instance with `transparent: true, opacity: 0.35`; swap
  materials per frame only when the hero cell changes (cheap: keep the
  set of cutaway cells and rebuild the affected mesh group).
- `GlViewport.setView('fps' | 'ortho')`; `main.ts` wires `F3`/`F2` to it
  and keeps the minimap/compass rose HUD from the `<pre>` grid.
- Tests: `tests/gl-ortho.test.ts` — `placeOrthoCamera` puts the camera
  north-west-above the hero (x < hero.x, z < hero.y, y > 0), frustum
  height gives the hero ≈ 1/7 of the rows, aspect correct; the cutaway
  set for a hero at (10,10) contains (11,11) and not (8,8) or (14,14).
