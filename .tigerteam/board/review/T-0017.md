## Goal
Two things the user saw in the first real session (screenshot 2026-09-03
20:53): standing in a corridor facing the one corridor tile they know,
the never-seen space beyond rendered as a solid brick wall, so an unknown
continuation looked like a dead end; and a pet dog next to them rendered
as a plain white square (a rectangle of `d`). Fix both in the renderer:
never-explored cells become a dark speckled void that reads as "unknown",
and sprites become shaped figures (tall ellipses for monsters, low ones
for items on the floor) with radial shading and a dark rim.

## Context
- `docs/render.md` (surface detail section), `src/render/raycast.ts`,
  `src/render/texture.ts` (T-0016). Keep `RaycastOptions.detail` semantics:
  `detail: false` stays byte-identical (flat golden unchanged); everything
  below is part of the default detail path and the textured golden is
  regenerated.
- **The unknown (`unexplored` kind).** Rays still stop at it (it is opaque:
  we know nothing beyond), but paint it as a veil, not a wall: base colour
  `[0.03, 0.03, 0.05]`, no brick texture, no top/bottom edge lines, no
  corner lines, plus `veilShade(u, v, seed)` in `texture.ts`: a sparse
  speckle — `0` for most samples, a value in `0.10–0.22` for about 12 % of
  them chosen by the existing hash (stable per cell and per sample), added
  to the base. Under the quantizer this comes out as space, `.`, `` ` ``
  and `'` glyphs in near-black: dark static, visibly different from
  masonry. Depth is still written (sprites/fog unaffected).
- **Known rock (`stone` kind, i.e. an `S_stone` glyph NetHack actually
  displayed)** stays a flat dark grey `[0.12, 0.12, 0.13]` without texture
  but with the top edge line, so it reads as "solid, known" and differs
  from both bricks and the veil. (Corridor sides and dead ends are
  `unexplored` in NetHack's own model — it never displays the rock around
  corridors — so a corridor becomes a lit path through darkness, which is
  exactly the information the game gives.)
- **Sprites as figures.** Replace the rectangular billboard fill:
  - Monsters (`cls` mon, pet, ridden, detected, invisible, statue): a
    standing figure 0.45 cells wide × 0.9 tall, base on the floor. Inside
    the screen bounding box, a cell is part of the figure when its
    normalised offset `(dx, dy)` from the centre satisfies
    `dx² + dy² ≤ 1` (an ellipse); its brightness is
    `0.55 + 0.45 · (1 − (dx² + dy²))` times the sprite colour (before
    fog). Cells in the ring `1 < dx² + dy² ≤ 1.35` get the letter at 0.22
    brightness (a dark rim that separates the figure from whatever is
    behind it). Every figure cell prints the sprite's letter.
  - Items (`cls` obj, body): a low shape 0.4 wide × 0.3 tall whose bottom
    sits on the floor row for its distance (`horizon + 0.5·fV/tY`), same
    ellipse shading and rim, so items read as things lying on the floor.
  - Far sprites (fewer than 2 cells tall) collapse to the single letter at
    full brightness with no rim, as today.
  - Depth test per cell as today; figures still occlude by depth.
- Golden: regenerate `tests/raycast-textured-golden.txt`. The scene should
  include one monster sprite and one item sprite (add them to the golden
  render call) so the shapes are pinned.
