## Goal
`ssh play@host` drops straight into AsciiHack (first-person mode), one
NetHack playground per player name, and the ssh session ends when the
game exits. Everything a host operator needs is a script plus a doc.

## Context
- The client already runs from `npm start` (tsx) — see `README.md`,
  `docs/ui.md`, `src/cli.ts` flags (`--mode`, `--name`, `--bridge`,
  `--playground`, `--theme`). `npm run build` emits `dist/` via
  `tsconfig.build.json`; `node dist/cli.js` must work identically to
  `npx tsx src/cli.ts` (check it — fix ESM import suffixes if anything
  breaks; `package.json` itself is PM-owned, so if a `bin` entry is
  needed write the exact JSON you want into `package.json.bin-note.md`
  and the PM will apply it).
- `bin/asciihack-login` (bash, executable): the login shell for a
  dedicated `play` user. Behaviour: `TERM` defaults to `xterm-256color`
  when unset or `dumb`; the player name comes from `$SSH_ORIGINAL_COMMAND`
  when it is a single `[A-Za-z0-9_-]{1,20}` token (so
  `ssh play@host mia` plays as `mia`), otherwise a `read -p 'Name? '`
  prompt (same validation, three attempts, then exit 1); playground is
  `$ASCIIHACK_HOME/players/<name>` (default `$HOME/.asciihack`), created by
  copying `build/nethack/bridge/playground` on first use; then
  `exec node dist/cli.js --mode=fps --name=<name> --playground=<dir>`
  with `--bridge` pointing at the repo's build. Refuse to run with a
  helpful message if `dist/cli.js` or the bridge is missing. Put the
  name-validation and path logic in a sourceable `bin/asciihack-lib.sh`
  so the test can exercise it without ssh.
- `scripts/ssh-serve.sh`: `--check` verifies dist + bridge + playground
  and prints the `sshd_config` snippet; `--setup` (needs root, prints what
  it would do with `--dry-run`) creates the `play` user with
  `bin/asciihack-login` as its shell, and appends a
  `Match User play` block with `ForceCommand`, `PasswordAuthentication
  no`/`PermitEmptyPasswords yes` alternatives explained in the doc,
  `X11Forwarding no`, `AllowTcpForwarding no`, `PermitTTY yes`.
- `docs/ssh.md`: the operator walk-through (build, setup, test with
  `ssh -t play@localhost mia`), how names map to playgrounds, how saves
  persist, the security notes (no shell, no forwarding, NetHack's own
  `#shell`/`!` are compiled out with `NOSHELL`), and the terminal
  requirements (≥ 80×24, 24-bit colour; `--theme` choice for weak
  terminals).
- Keep tests to the pure pieces: `tests/ssh-wrapper.test.ts` runs
  `bash -c 'source bin/asciihack-lib.sh; ...'` for name validation
  (accepts `mia`, `Mia_2`; rejects empty, `../x`, 21+ chars, spaces) and
  the playground path derivation. Nothing that needs sshd.
