## Goal
`renderOrtho(level, hero, sprites, fb, opts)` — the Diablo/Fallout-style
isometric view of the remembered NetHack map, drawn into a `FrameBuffer`
exactly like the raycaster does, so the same quantizer and screen writer
show it. Pure and deterministic; golden-tested.

## Context
- Read `docs/architecture.md` §5.1, §5.3, §7 and `docs/render.md` (the
  raycaster's conventions and golden workflow — copy them). Types are
  PM-owned in `src/model/types.ts`; reuse `KIND_COLORS` and `CEILING_COLOR`
  from `src/render/raycast.ts` (merged) and `levelFromAscii`/`ROOM`/
  `L_SHAPED` from `tests/fixtures/levels.ts`.
- **Projection (locked).** Map cell `(x, y)` (x east, y south) has the screen
  anchor `sx = 2·(x − y) + ox`, `sy = (x + y) + oy` where `(ox, oy)` is
  chosen so the hero's anchor lands at `(floor(cols/2), floor(rows/2))`.
  Its floor is a **brick of 4 columns × 1 row**: columns `sx−2 … sx+1` of
  row `sy`. Bricks on consecutive rows are staggered by 2 columns, so every
  screen cell belongs to exactly one map cell. Inverse: for screen `(c, r)`
  (origin-relative `c' = c − ox`, `r' = r − oy`): `p = r' mod 2` (non-negative),
  `k = floor((c' + 2 − 2p) / 4)`, `d = 2k + p` (this is `x − y`),
  `x = (r' + d) / 2`, `y = (r' − d) / 2` — both integers. Export
  `cellToScreen(x, y, origin)` and `screenToCell(c, r, origin)`.
- **Painter's order.** Draw map cells in increasing `x + y`, ties by
  increasing `x` (north-west to south-east), only those whose bricks can
  touch the viewport. Every draw writes `rgb`, `depth = x + y` and clears
  `overlayCh` for the cells it covers, so later (nearer) draws occlude.
  Pre-fill the buffer each frame (`rgb` 0, `depth` Infinity, overlay 0) the
  way `renderFirstPerson` does — every cell must be written every frame.
- **Floor cells** (`!isSolid(kind)`, kind ≠ `unexplored`): the brick in
  `KIND_COLORS[kind]`, with the two outer columns (`sx−2`, `sx+1`) at 85 %
  so tile edges read. `doorway`/`door_open` are floor in the door colour.
- **Wall-like cells** (`isSolid(kind)` and kind ≠ `unexplored`): a block
  extruded `opts.wallRows` (default 2) rows up: the vertical face is the
  brick at row `sy` and the rows `sy−1 … sy−wallRows+1` at 60 % of
  `KIND_COLORS[kind]` (south-east face, in shadow), and the top face is the
  brick at row `sy − wallRows` at 100 % (lit). `unexplored` cells are not
  drawn at all (stay black, depth Infinity), so the dungeon floats in
  darkness like the classic map.
- **Sprites**: for each `Sprite` whose cell is in view, when its tile is
  drawn (same painter step) write `ch` into `overlayCh` at `(sx, sy−1)` and
  `(sx−1, sy−1)` — two columns so letters read at 4-wide tiles — with
  `overlayRgb = rgb` (attenuated like the tile); a wall drawn later covers
  them (that is the occlusion). The hero is an ordinary sprite here (the
  caller passes the `@`); do not special-case it.
- **Fog**: multiply every drawn colour by `exp(−opts.fogK · dist)` with
  `dist` the Chebyshev distance from the hero cell (default `fogK` 0.06),
  so far parts of the level fade.
- `OrthoOptions { wallRows?: number (2), fogK?: number (0.06) }`.
- Golden: `ROOM` with the hero at its centre, 80×24, quantized with the same
  **test-local** 10-glyph ramp the raycaster test uses (copy it; do not
  import `src/render/ascii.ts`), compared to `tests/ortho-golden.txt`,
  regenerated with `UPDATE_GOLDEN=1`.

### Notes for the reviewer
- **Geometry finding (worth a look).** In this staggered 4×1 brick projection, a
  single wall can never cover *both* of a sprite's two overlay cells
  (`(sx, sy−1)` and `(sx−1, sy−1)`): covering both requires the wall's brick to
  share the sprite's column span, which forces it to be the sprite's own cell.
  I verified this by brute force. So the "sprite behind (north-west of) a wall is
  fully covered" criterion is implemented with two walls (east + south, both
  drawn after the sprite), each covering one cell → 0 overlay cells; the open
  sprite writes exactly 2. A single east wall leaves exactly 1 cell (asserted
  implicitly by the 2/0 pairing). If the intended single-wall occlusion differs,
  that's a spec-vs-geometry point to resolve.
- All other criteria (round-trip, centred hero brick, 4-cell floor at 85 %,
  `wallRows+1` wall rows with lit top, half-brick occlusion, fog, unexplored
